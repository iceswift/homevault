# HomeVault v0.1.0-preview.2

Experimental Linux preview focused on clearer terminal operation and evidence.
Start with generated data and a byte-verified restore. This is not a stable release,
bootable server image or proof of complete host recovery.

## New since Preview 1

- `tui-demo`: synthetic design preview; no configuration or backup tools required.
- `tui-status --plan FILE`: combined, strictly read-only workflow view with explicit
  backup/check, recorded source freshness, plan gates and uninspected recovery.
  It reads local metadata without opening credentials, discovering tools or
  contacting services. Disabled gates do not erase earlier backup evidence.
- `--config FILE tui-jobs`: separate manual file-only backup/check UI with exact
  typed project confirmation, progress from engine records and cancellation cleanup.
  Review binds configuration and previous-job identity again under the engine lock.
  Database, capture-required and recovery-only jobs are blocked in this mode.
- Manual UI `h` shows bounded local attempt history; `d` shows metadata diagnostics
  and next actions. Missing tools keep diagnostics open with job execution blocked.
- Explicit `--context lab|production|unknown` labels. These are operator-supplied
  display labels; they do not select or validate a configuration or change guards.
- First-user trial guide/form, contribution/security policies, FAQ and improved
  public documentation. Independent first-user feedback remains pending.

## Choose a mode

```sh
./homevault tui-demo
./homevault tui-status --plan /absolute/reviewed-workflows.json --context production
./homevault --config /absolute/reviewed-files.json tui-jobs --context lab
```

Use only generated file data for a first manual-job trial. The last command is
operational after confirmation; its Lab label does not prevent choosing real data.
It invokes native manual jobs, not coordinator workflows: coordinator enabled flags
and maintenance windows are not loaded. Configured notifications can follow a
confirmed job. Read the bundled TUI guides before trying actions.

## Upgrade and compatibility

Existing CLI/`tui` entry points, configuration schema and repository keys are retained.
No application-data migration is introduced. Opening these views does not install
services, enable schedules, activate retention or update an existing server.
Keep the original key/config when adopting an existing repository; never initialize
over real backups to follow a generated-data demonstration.

Ubuntu/Linux amd64 is runtime-tested. ARM64 is cross-built and structurally checked
only; native execution remains unverified. No Windows/macOS deployment package is
supplied. Restic/rclone are separate dependencies. The bundled walkthrough needs
Bash and Python 3.11+. CI uses Restic 0.19.1 and optional age 1.3.2; operator cloud
evidence used rclone 1.75.2. These are tested versions, not universal compatibility.

## Candidate verification

Inspect the exact tag's successful draft-release workflow before publication. It
runs Go race tests/vet, package-verifier negative checks, generated-data recovery,
checksums/metadata/ELF validation and backup/check/byte-verified restore from the
extracted amd64 package. New packaged TUI frame checks run with an empty PATH and
verify generated fixture hashes, mode bits, modification times and tree membership
remain unchanged. Tool-less manual jobs stay blocked.

Frame checks do not establish interactive UX, application recovery, cloud
reachability or ARM64 runtime support. Separate operator PTY and selected-app
recovery rehearsals do not replace independent onboarding or replacement-host
recovery evidence. A stored successful upload is not fresh source data or recovery
proof. No automatic stale-lock deletion, data pruning or production cutover occurs.

Expected assets are amd64 and ARM64 `.tar.gz` archives plus `SHA256SUMS`. Each archive
contains `RELEASE.json` with its exact source commit/version/toolchain. Checksums
detect corruption, not independent publisher authentication; signatures/provenance
attestations are not supplied. A draft is not a published download, and existing
Preview 1 assets are unchanged.
